# 双路充电控制与网页

## 移植范围

以 demo 的 Arduino 充电控制程序为行为与报文来源，改为本机 ESP-IDF 6.1 原生组件。
所有源文件、网页、mDNS 与许可均在 `fireware` 内；编译和运行不读取 `demo`。
实体屏幕继续运行 480×320 LVGL benchmark，未移植旧 LovyanGFX 屏幕 UI、EC11 编码器
或旧板引脚。后续 LVGL 触摸 UI 可直接调用 `charger_service.h`，不必重写协议和控制任务。

迁移了 CC/CP、5 组预设、启动电流爬坡、功率/停充电流保护、AH/WH/次数、参数持久化、
地址查询/扫描、网页画布与键盘、波形、25 色配色、Wi-Fi 配网、PIN、SNTP、mDNS、重启和 OTA。
网页新增两路选择与总览，各路参数、地址、运行状态、保护、统计、锁定完全独立。
配色、网络、网页端口、PIN 和 GPIO13 蜂鸣器属于整块控制板。

浏览器通过控制板 HTTP 服务控制板上两路 485。旧网页中的 Web Serial/DTU 直连模式不再显示，
以免绕过板上周期、保护和状态管理；旧网页中不同于 MCU 逻辑的开关机值也未沿用。
旧屏幕复位、编码器连按急停、PWM 音量和可调保活参数已移除，网页提供明确的停止按钮。

## 首次使用

1. 在 `fireware` 执行 `.\build.ps1 build`，然后通过 USB Serial/JTAG 完整烧录：

   ```powershell
   .\build.ps1 -IdfArgs @('-p', 'COM5', 'flash', 'monitor')
   ```

   COM5 换为实际端口。本次从旧 1 MB factory 表改为 `partitions.csv`：20 KiB NVS、
   8 KiB OTA 元数据、两个 4 MiB 应用槽。首次升级必须烧录新的分区表与应用，不能只用
   旧固件的 OTA/`app-flash`。烧录整套镜像也适用于未连接充电器时的升级。

2. 连接热点 **ChargerCtrl**，密码 **12345678**；访问 **http://192.168.4.1/**，
   自动跳转到默认网页端口 **8899**。初始控制 PIN 为 **1234**，网页可修改。
   STA 配网后同一网页也可经路由器分配的 IP 或支持 mDNS 的客户端 `http://charger.local/` 访问。
   AP 始终开启，避免尚未移植实体 UI 时失去配网入口。路由器连接失败每 15 秒重试，
   不影响两路充电任务。配网时需重新输入 Wi-Fi 密码，设备不通过 API 回显密码。

3. 两路默认各为 **9600、8N1、设备地址 0**。UART1：TX17/RX18/DE21；
   UART2：TX11/RX12/DE14。两路分别接两台充电器，不能把两组 A/B 并到同一总线。
   选择 `485-1` 或 `485-2` 后单独设置参数；串口格式在 menuconfig 分别配置。
   地址不同可在停止状态扫描或手填，扫描只展示结果，保存设置后才切换地址。
   切换后先向新地址请求停止，再允许启动。

4. 上电**不恢复充电运行**：两路先发关机请求并读取状态。网页显示 `已确认停止` 后可启动。
   没有设备或应答丢失时显示 `等待OFF应答`/离线，不把发送成功当成关机成功。
   已经尝试开机而尚未确认关闭时，禁止改地址、OTA 和重启。

5. GPIO13 为有源蜂鸣器开关：HIGH 响、LOW 停，初始化先输出 LOW。网页按钮可开/关，
   重启恢复关闭，不保存鸣叫状态；本版不自动鸣叫、不占用 LEDC、不提供 PWM 音量。
   GPIO40 长按 2 秒切换触摸、GPIO41 200 ms 只读滤波维持原行为。

## 两路控制和时序

- 每路独立任务、配置、锁、读写状态；一路超时不阻塞另一路的 UART 事务。
- 空闲时读取状态，**不周期写入电压/电流、不自动开机**。每次读取完成后约 500 ms 再读，
  单次收发超时参数为 250 ms；地址扫描逐项进行，不在 HTTP 请求中阻塞扫描。
- 启动时立即写入初始电压/电流，初始电流为 `min(1 A, 目标电流)`；确认写入后立即开机，
  只有开机应答正确才显示运行并计次。初始预装不等待 15 秒，以免启用充电器残留参数。
- **运行中电压/电流写命令每路间隔 15,000 ms**，从上一笔设定事务结束计时。
  修改设定只更新待发送值，下一个周期生效。任务调度或当时正在进行的读取可能带来少量延后。
  写入失败直接进入保护停机，不用密集重写设定值来掩盖故障。
- 开机、主动停止、保护停机不受 15 秒计时限制。已在执行的 UART 事务先结束，再处理停止。
  OFF 无应答时约每秒重试，继续显示未确认状态；通信恢复不会自动重新启动。
- 原 demo 的循环 ON 保活已移除，避免在停止竞争或周期外反复开机。所接充电器能否接受
  15 秒设定周期、是否另有厂家保活要求，需使用对应型号实板确认。
- 爬坡按经过的时间计算，默认每秒增加 0.05 A，在每次 15 秒写入时采样，所以线上的电流
  步进通常约为 0.75 A。降低目标电流也会生效。CC 的保护功率为目标 V×A；
  CP 与 demo 一样按 `目标电流 = 目标功率 / 目标电压` 计算，并非基于实测电压闭环调节。
- 两次连续实测功率超过对应已应答目标功率的 110%，触发 `PWR`；硬件状态位触发
  `OCP`/`SHORT`/`OTP`。尚未发送的较低目标不会提前造成误保护；绝对最大功率仍受当前配置约束。
- 停充电流保护先要求见过达到阈值的电流，且启动超过 10 秒，之后低于阈值触发 `TRKL`。
  设为 0 禁用。连续 3 次状态读取失败触发 `COMM`，启动写入/开机失败为 `START`，
  运行中设定写入失败为 `WRITE`。故障须重新人工启动，错误未消失时启动会被拒绝。
- AH 直接积分实测电流，WH 积分实测功率，不沿用旧 `WH/设定V` 的 AH 近似。
  无效读数和大于 2 秒的采样间隙不积分。每次成功启动清空本次 AH/WH，次数累加；
  运行中约每分钟及启动/确认停止时保存，突然断电最多丢失最近一分钟统计。
- 设置和统计用带版本的 NVS 数据保存；保存失败向网页报告错误。运行、锁定、触摸开关、
  蜂鸣器开关不持久化。锁定阻止改参数/启动，**停止始终允许**。

## 厂家 RTU 协议

`charger_codec.c` 单独实现 demo 方言，通用 `modbus_rtu` 的 `03/04/06/10` API 保留。
厂家协议中的地址 0 是有应答的单设备地址，不能当成通用 Modbus 广播。

| 操作 | CRC 之前的数据 | 正常应答 |
| --- | --- | --- |
| 状态读取 | `addr 03 00 01 00 03` | `addr 03 06 Vhi Vlo Alo Ahi Shi Slo CRClo CRChi` |
| 开机 | `addr 06 00 00 00 FF` | 8 字节完整回显 |
| 关机 | `addr 06 00 00 00 00` | 8 字节完整回显 |
| 电压/电流 | `addr 0F 00 01 00 02 Vhi Vlo Ahi Alo` | 前 6 字节回显 + CRC |
| 查询地址 | `DD DD 00 01` | `DD DD 00 01 00 addr CRClo CRChi` |

电压倍率 10、电流倍率 100；只有读取电流是小端。`0x0F` 无字节计数字段，
不是标准写线圈。所有响应检查长度、地址/功能、CRC，写入检查回显，异常帧不当成功。
状态低 4 位为 IDLE/BOOT/CHG/FULL/LIM；`0x40/0x20/0x10` 为 OCP/SHORT/OTP。
沿用 demo MCU 侧规则，`0x80` 不当作 OVP，避免 `0x0082/0x2082` 正常状态误停机。

## 网页与 API

网页本地嵌入，无 CDN、字体或 JS 网络依赖；主界面保留 demo 的网页画布风格，
这不是实体 LCD UI。选路时清空波形并取消未确认操作；旧通道响应不会覆盖新通道。
波形保留当前页面最近 240 个有效样本，断线期间不补造测量值，横轴按样本秒近似显示。

除根页面和 OTA 专用入口外，API 要求明确的 `ch=1` 或 `ch=2`。
只读状态/参数公开，修改操作统一 POST，并通过 `X-Charger-PIN` 请求头认证；
也兼容 `pin` 表单/查询字段。未移植旧 demo 的固定管理员后门。
非法参数返回 400，PIN 错误 401，运行状态冲突或保存失败 409，前端会显示错误。

| API | 方法与参数 |
| --- | --- |
| `/state` | GET；含测量、在线/停止确认、待写倒计时、统计、保护、扫描状态 |
| `/settings` | GET；POST：`port,maxV,maxA,maxP,rampMs,rampSt,addr`；编辑系统设置前停止该路 |
| `/setparam` | POST：`field=setV/setA/trickle/pwrMax,val`；CP 电流与 CC 功率由公式计算 |
| `/btn` | POST：`id=start/stop/cc/lock/clr/clrall`；明确 start/stop，不用远程盲切换 |
| `/presets` | GET；5 组 `[V,A]` |
| `/preset`、`/preset_set` | POST：`n=1..5`；编辑另加 `v,a` |
| `/scan` | POST；仅该路非运行时允许；查询后最多扫描 0～247 |
| `/theme`、`/theme/reset` | GET 当前 25 色；POST `c=rrggbb,...` 保存，reset 恢复 |
| `/wifiget`、`/wifisave` | GET 需 PIN，仅返回 SSID；POST `ssid,pass` 配网 |
| `/pinset` | POST：用当前 PIN 认证，`new` 为 4～16 字节新 PIN |
| `/buzzer` | POST：`on=0/1`；全局 GPIO13 |
| `/reboot` | POST；两路都确认停止且未扫描时接受 |
| `/update` | POST；原始应用 `.bin` 二进制请求体，不使用 multipart；需要 PIN |

网页端口修改保存后重启生效；80 端口跳转和 mDNS 服务发布指向本次实际监听端口。
OTA 仅接受应用文件 `build/esp32s3_basic_drivers.bin`，最大 4 MiB；按 ESP-IDF 校验镜像后
才切换启动槽，错误/中断会终止升级并返回失败，不报告假成功。升级期间阻止新的启动请求。
需两台充电器均确认停止；设备未连接而无法获取 OFF 应答时可通过 USB 完整烧录。

## 验证与实板验收

```powershell
& 'C:\Espressif\tools\python\v6.1\venv\Scripts\python.exe' tests/test_charger.py
node tests/test_web.cjs

```

充电测试把真实 service/codec/policy 编译为主机程序，模拟时钟和 UART 应答：双路周期、
低电流目标、启动失败、关机重试、停止与启动竞争、通信故障、功率/停充/硬件故障保护、
维护互斥、锁定、存储失败、地址扫描、AH/WH 积分均有覆盖。网页测试执行实际内嵌 JS，
检查 DOM 绑定、选路、命令/认证、错误反馈、旧响应抑制与画布调用。
通用 Modbus、双路 UART 并发、坐标、按键和触摸防误触原有 19 组测试保留。

以上属于编译和主机模拟，不能替代真实 Wi-Fi、RTU 时序、充电器电气行为和 OTA 掉电验证。
本轮未检测到串口设备，没有烧录或声称实板充电成功。上板时分别确认：

1. GPIO13 上电/复位静音及网页开关；LCD benchmark、GPIO40/41 正常。
2. 两台充电器的地址、波特率、厂家报文与 CRC；逻辑分析仪确认两路 DE 和 15 秒设定间隔。
3. 两路不同设定同时运行，停止一路不影响另一路；拔掉一路后的 COMM 保护与重连不自启。
4. 开机/关机应答丢失、降流、功率与停充阈值、保护后 OFF 重试。
5. AP/STA 配网、断网重连、mDNS、端口修改、PIN、NVS 重启保存和两槽 OTA 成功/失败路径。
